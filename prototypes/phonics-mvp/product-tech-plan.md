# 音标星球 · 移动端一期产品与技术方案

## 1. 一期目标

一期只验证一个最小闭环：

```text
选音标 → 学发音 → 做 3 题过关检查 → 点亮关卡
```

不做家长端、付费、排行榜、教材同步词库、老师端，也不做复杂 AI 纠音。

## 2. 目标用户

- 学生：国内小学 3-6 年级，刚开始系统接触音标，单词拼读信心不足。
- 决策人：家长，但一期先不做家长端，只在产品定位里保留后续空间。
- 使用场景：每天 5 分钟，手机竖屏，课后碎片时间练 1-2 个音标。

## 3. 一期功能范围

### 3.1 48 音标学习地图

- 国内常用 48 音标口径：20 个元音 + 28 个辅音。
- 分组：
  - 短元音 7 个
  - 长元音 5 个
  - 双元音 8 个
  - 清辅音 9 个
  - 浊辅音 9 个
  - 其他辅音 10 个，包含 `/tr/ /dr/ /ts/ /dz/`
- 状态：
  - 未开始
  - 正在学
  - 已通过

### 3.2 单音标学习页

每个音标固定结构：

1. 播放标准发音。
2. 显示口型动作提示。
3. 展示 3 个例词。
4. 进入过关检查。

一期不追求长视频课，优先做短、可重复的练习。

### 3.3 过关检查

每个音标 3 题：

1. 听音选音标。
2. 看单词选目标音标。
3. 跟读并自评。

一期结果只分三档：

- 通过
- 接近
- 再练一次

## 4. 移动端页面

一期只需要 3 个核心页面：

1. **学习地图页**
   - 展示 48 个音标分组。
   - 默认推荐下一个要学的音标。

2. **音标学习页**
   - 大音标符号。
   - 播放按钮。
   - 口型提示。
   - 3 个例词。

3. **过关检查页**
   - 当前题目。
   - 选项。
   - 过关结果。
   - 下一关入口。

## 5. 技术方案

### 5.1 推荐技术栈

如果先做 App：

- Android 原生：Kotlin + Jetpack Compose。
- 本地数据：Room 或 DataStore。
- 音频播放：ExoPlayer / Media3。
- 打包音频：放在 `assets/audio/` 或 `res/raw/`。

如果先做最快验证：

- 移动端 Web / PWA。
- HTML + CSS + JS 或 Vue/React。
- 音频文件放在本地静态目录。
- 后续再转 Android。

建议路线：

```text
先用移动端 Web 原型验证内容和流程
  ↓
再做 Android MVP
  ↓
最后再补 iOS / 小程序
```

### 5.2 数据结构

```json
{
  "id": "ae",
  "symbol": "/æ/",
  "group": "short_vowel",
  "audio": "audio/phonemes/ae.mp3",
  "mouthTip": "嘴巴张大一点，声音短一点。",
  "words": [
    {
      "text": "cat",
      "audio": "audio/words/cat.mp3",
      "tip": "cat 中间就是 /æ/"
    }
  ],
  "checks": [
    {
      "type": "listen_choose_symbol",
      "answer": "/æ/",
      "options": ["/æ/", "/e/", "/ɑː/", "/ʌ/"]
    }
  ]
}
```

### 5.3 本地存储

一期只记录：

- 已通过音标列表。
- 当前学习音标。
- 每个音标最近一次检查结果。

不需要账号系统。

## 6. 音频方案

### 6.1 结论

一期音频建议：**自制音频 + App 内置**。

原因：

- 不花钱。
- 版权最清楚。
- 离线可用。
- 不依赖网络。
- 48 个音标 + 少量例词，文件量很小。

### 6.2 不建议直接使用的来源

不建议把 Wiktionary / Wikimedia Commons 上的发音文件直接打包进产品作为默认音频。

原因：

- 很多文件是 CC BY、CC BY-SA 或其他授权，不是无条件免费商用。
- 需要准确署名、保留许可、处理相同方式共享要求。
- 文件来源分散，音质、口音、音量不统一。
- 后续如果做商业化，授权管理会变成长期风险。

也不建议从 YouTube、词典网站、教材 App、网课视频里截音频，这些都容易侵权。

### 6.3 可行的免费合规方案

优先级从高到低：

1. **自己录制**
   - 找英语老师、英语较好的成人、留学生或团队成员录制。
   - 录制前签一份简单授权：允许项目永久免费/商业使用、修改、剪辑、分发。
   - 最稳，推荐。

2. **使用 CC0 / Public Domain 音频**
   - 只用明确标注 CC0 或公有领域的音频。
   - 逐条保存来源链接和许可证截图。
   - 适合补充，不适合作为主来源。

3. **浏览器 / 系统 TTS 作为临时占位**
   - 可以用于早期交互测试。
   - 不建议作为正式学习音频，因为音标、口型和儿童教学质量不可控。

4. **开源 TTS 离线生成**
   - 只适合作占位或辅助。
   - 音质和自然度通常不适合正式儿童发音教学。
   - 需要逐项确认 TTS 引擎、模型、声音库的许可。

### 6.4 内置还是线上

一期建议：

```text
标准音频：内置
学习配置：本地 JSON
后续更新：预留线上配置接口
```

不要一期就依赖线上音频。

理由：

- 小学生使用场景经常是家长手机、网络不稳定。
- 音频文件总量小，内置成本低。
- 版权文件跟 App 包一起管理，更清楚。
- 线上音频会引入 CDN、缓存、隐私和可用性问题。

后续二期可以做：

- 内置基础 48 音标。
- 线上下发新增例词音频。
- 增量资源包下载。

### 6.5 音频文件规模估算

一期最小音频：

- 48 个音标标准音。
- 每个音标 3 个例词，共 144 个单词音频。
- 每条音频 1-2 秒。

使用 `mp3` 或 `m4a` 后，总体大约几 MB 到十几 MB，适合内置。

## 7. 录音制作规范

### 7.1 录音内容

每个音标录：

1. 单独音标音。
2. 3 个例词。
3. 可选：一个短句，不放一期首版。

### 7.2 录音要求

- 安静房间。
- 手机或普通麦克风即可。
- 每条音频前后留 0.2 秒空白。
- 声音音量统一。
- 只录发音，不加背景音乐。
- 导出格式：`mp3` 或 `m4a`。

### 7.3 授权要求

录音人需要确认：

```text
我授权本项目永久、免费、可商用地使用、复制、修改、剪辑和分发这些录音。
```

授权记录放到项目文档中保存。

## 8. 一期开发顺序

1. 移动端 Web 原型确认。
2. 整理 48 音标 JSON 数据。
3. 先用占位音频接通播放流程。
4. 自录 10 个音标测试音频。
5. 完成学习地图、学习页、检查页。
6. 小范围给 3-5 个孩子试用。
7. 根据反馈再录完整 48 音标音频。
