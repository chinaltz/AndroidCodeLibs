# 文章全面审查

按照博客的5条内容原则和写作模板，对待审文章进行全面审查。

## 审查维度（逐项打分：✅通过 / ⚠️需改进 / ❌不通过）

### 原则1：先讲人话，再讲术语
检查要点：
- [ ] 第一个出现的概念是否先用比喻/场景解释过？
- [ ] 术语是否只在必要时出现？出现时有没有附带通俗解释？
- [ ] 是否有术语堆砌的段落（一段内超过2个术语）？
- [ ] 用"普通人读一遍能否理解核心意思"做最终判断

### 原则2：先解决问题，再展示技术
检查要点：
- [ ] 开头是否先描述了读者会遇到的真实场景或痛点？
- [ ] 正文的目的是为了帮读者解决问题，而非炫耀作者的知识？
- [ ] 有没有出现"为了讲技术而讲技术"的段落（讲了但读者用不上）？
- [ ] 每段内容是否能回答读者心里"这跟我有什么关系"的问题？

### 原则3：不制造焦虑
检查要点：
- [ ] 是否存在"不会AI就完蛋了"式的恐慌表述？
- [ ] 是否夸大了AI的能力或威胁？
- [ ] 讲风险时是否同时给出了应对方法？
- [ ] 语气是否平和、理性、不给读者施压？

### 原则4：不假装万能
检查要点：
- [ ] 是否明确说了AI做不到的事？
- [ ] 是否给出了具体的边界和限制条件？
- [ ] 是否避免使用"所有""永远""一定"等绝对化表述？
- [ ] 示例提示词是否可能在实际使用中产生问题？（如有，标注）
- [ ] 边界提醒是否服务于读者行动？如果只是机械列出“AI适合/不适合”，建议删除或融入正文

### 原则5：每篇都有带走的东西
检查要点：
- [ ] 结尾是否有"今天小结"或等价的收尾？
- [ ] 读者读完后能否说出今天学会了什么（1-3件事）？
- [ ] 是否有1个可以立刻照做的具体动作？
- [ ] 是否有可复用的提示词模板？

### 模板结构检查
检查要点：
- [ ] 有无吸引人的标题？
- [ ] 开头有无生活场景切入？
- [ ] 有无一句话核心结论？
- [ ] 正文是否有比喻 + 场景 + 必要边界/取舍？
- [ ] 结尾是否有小结 + 行动建议？

### 语气检查
检查要点：
- [ ] 全文长句比例（超过30字的句子占比，应<20%）
- [ ] emoji 总数是否超过3个？（章节标题中的 emoji 不计入，仅统计正文段落中的 emoji）
- [ ] 括号解释是否过多（"（即……）""（也就是……）"）？
- [ ] 有无"众所周知""显然""毋庸置疑"等废话？
- [ ] 是否有作者自我分析、后台流程、备案认证费用等偏离读者收益的段落？如非必要，删掉
- [ ] 是否有“一句话结论”“今天只需要记住”“这一步的重点是”“一句话记住”等模板化表达？个人经验类文章应改成自然复盘口吻

### 敏感词检查
检查要点：
- [ ] 是否出现「翻墙」「科学上网」「梯子」「VPN」等敏感词？改用「特殊网络环境」「网络加速工具」
- [ ] 工具举例时是否优先使用国内直连工具？（开头/正文示例应优先用豆包、Kimi、DeepSeek 等）
- [ ] 是否有其他可能引发平台审核风险的表述？

### 作者手写开篇检查
若文首含 **「自己写的：」** 块（见 `.agents/skills/author-preface-article/SKILL.md`）：
- [ ] 结构是否为：`自己写的：` → 手写正文 → `---` → `下面是AI 写的` → 标题
- [ ] 手写块是否仍在全文最上方且逐字未改？
- [ ] `下面是AI 写的` 是否存在且为固定文案（非变体）？
- [ ] AI 段是否重复了手写块中的动机、协作方案等内容？
- [ ] 是否误删为「草稿备注」？

## 输出格式

