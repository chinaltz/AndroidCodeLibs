## 先说人话：Skill 就像给新员工的一张 SOP

你可以把 AI 想成一个很聪明的新同事。

它会写字，会查资料，会总结，也能帮你改代码。

但它有一个问题：

每次接新任务，都要重新听你讲规则。

比如你要它帮你写公众号文章，你可能每次都要说：

```text
请用口语化风格。
不要写得太像论文。
每段短一点。
先给生活例子。
最后给可操作步骤。
```

说一次还行。

每次都说，就很烦。

Skill 的作用，就是把这些规则提前写好。

下次你说：

```text
用我的博客风格，写一篇 Skill 科普文。
```

AI 看到 Skill 后，就知道：

```text
这类文章要写给普通人
  → 先讲生活比喻
  → 再解释术语
  → 给步骤和提示词
  → 最后引导下一步行动
```

所以 Skill 不是魔法。

它更像一张 SOP。

也就是工作说明书。

你把做事方法写清楚，AI 就少走弯路。

## Skill 是怎么发展起来的？

Skill 不是突然冒出来的。

它其实是 AI 工具一路变强之后，自然长出来的东西。

可以按这条线理解：

```text
提示词
  → 长提示词模板
  → 项目说明文件
  → 可复用 Skill
  → Skill 社区和市场
```

### 第一阶段：大家先学会写提示词

最早大家用 AI，主要靠一句一句问。

比如：

```text
帮我写一篇公众号文章。
```

后来大家发现，问得越清楚，结果越好。

于是提示词开始变长：

```text
你是一个公众号写手。
请用口语化风格。
目标读者是普通人。
每段不要太长。
结尾给一个行动建议。
```

这时候还没有 Skill。

但 Skill 的影子已经出现了。

因为大家已经在做一件事：

把经验写成规则，让 AI 按规则输出。

### 第二阶段：长提示词变成固定模板

再往后，很多人开始保存自己的提示词模板。

写周报有一套。

写短视频脚本有一套。

写小红书标题有一套。

做代码审查也有一套。

问题是，模板越多越乱。

你要复制、粘贴、改变量。

有时候还会忘记某个关键要求。

这时候大家需要的不只是“一个提示词”。

而是“一个可以反复调用的能力包”。

Skill 就是在这个需求上出现的。

### 第三阶段：AI 编程工具开始需要项目规矩

等 AI 开始帮人写代码，问题又变复杂了。

它不只要回答一句话。

它还要看项目文件、改代码、跑命令、查报错。

这时候光靠聊天已经不够。

你需要提前告诉 AI：

```text
这个项目的目录结构是什么
代码风格是什么
哪些文件不能乱动
改完后要跑哪些检查
遇到错误先看哪些文档
```

所以 AGENTS.md、CLAUDE.md、项目规则文件开始流行。

它们解决的是：

让 AI 先了解这个项目的“公司制度”。

Skill 再进一步。

它解决的是：

遇到某一类任务时，AI 应该按哪套“办事流程”做。

### 第四阶段：Claude、Codex 这类工具把 Skill 做成正式能力

到了 2025 年左右，Skill 开始从“大家自己写提示词模板”，变成 AI 工具里的正式能力。

Claude Code 开始提供 Skills。

它的思路是：

把某一类任务的说明、脚本、参考资料放在一个文件夹里。

AI 需要时再加载。

这样既不用每次把所有规则塞进对话里，也能让复杂任务更稳定。

OpenAI 的 Codex App 也开始支持 Skills、插件和项目规则这一套组合。

你可以把它理解成：

AI 不再只是一个聊天窗口。

它开始像一个能长期工作的助手。

要长期工作，就需要记住流程、工具和规矩。

Skill 正好负责这部分。

### 第五阶段：SkillHub 让普通人也能先逛起来

再往后，就出现了 SkillHub 这类网站。

腾讯云 SkillHub 的价值，不只是给技术人看。

它更像一个 Skill 展示区。

普通人可以先不用学怎么写。

先看别人已经做了哪些 Skill：

```text
写作
办公
学习
编程
运营
资料整理
```

这一步很重要。

因为一个东西只有被普通人看见、收藏、复用，才会从“技术功能”变成“日常工具”。

所以 Skill 的发展，可以用一句话概括：

> 从“我临时告诉 AI 怎么做”，发展到“我把做事经验沉淀成一个可复用能力”。


你会发现，Skill 的价值不是替你“灵感爆发”。

## Skill 能做什么？

Skill 最核心的作用，是让 AI 在某类任务上「更像熟手」。

它不是让 AI 突然变聪明。

而是让 AI 少问废话，少乱发挥，少踩重复的坑。

### 1. 固定你的写作风格

比如我们做「技趣星球」这个博客，就可以写一个文章 Skill。

里面规定：

```text
目标读者：普通人，不是专业程序员
语气：像朋友聊天
结构：先生活场景，再一句话结论，再步骤
限制：不要堆术语，不要制造焦虑
输出：给可复制的提示词
```

这样每次写文章，AI 不用从零理解你的风格。

你可以直接说：

```text
请按技趣星球风格，
写一篇给普通人看的 AI 工具扫盲文。
主题是：Skill 是什么。
要求结尾给一个可以立刻照做的小练习。
```

这就是 Skill 的第一种用法：

把你脑子里的写作习惯，变成 AI 能读懂的规则。

### 2. 固定一套做事流程

有些任务不是一句话能完成的。

比如发布一篇文章，可能要做这些事：

```text
选题
  → 写初稿
  → 润色
  → 起标题
  → 做配图方案
  → 审查
  → 导出 HTML 和 Word
```

如果每次都手动提醒 AI，很容易漏步骤。

Skill 可以把流程写下来。

你只要说：

```text
按发布流程处理这篇文章。
```

AI 就知道先后顺序。

这类 Skill 特别适合重复工作。

比如写周报、整理会议纪要、生成短视频脚本、制作发布清单。

### 3. 告诉 AI 项目的规矩

如果你让 AI 改代码，最怕它不懂项目规矩。

比如：

```text
这个项目不能随便改目录结构。
新增文章要放在 content/posts 下面。
图片路径必须写 ./images/xxx.png。
改 plan 目录后要同步上下文。
```

这些规矩如果只靠聊天告诉 AI，很容易忘。

写进 Skill 或项目说明后，AI 每次做相关任务都会先看规则。

这对长期项目很有用。

你不是每次都重新培训 AI。

你是在给它一本项目手册。

### 4. 帮 AI 学会调用工具

有些 Skill 不只是写文字规则。

它还会告诉 AI：

遇到某类任务，应该用哪个脚本、哪个命令、哪个工具。

比如：

```text
生成 Word 文档时，先运行导出脚本。
生成图片前，先检查图片目录。
改完前端页面后，要打开浏览器看一眼。
处理表格时，优先用表格工具，不要手算。
```

这就不只是「写作风格」了。

它开始像一个小型工作流。

AI 按说明一步步做，结果会稳定很多。

### 5. 把你的经验沉淀下来

Skill 最值得做的地方，是它能保存经验。

比如你发现：

某个平台标题不能太长。

某个导出命令容易漏图片。

某类文章必须先讲例子，不然读者看不进去。

这些经验如果只放在脑子里，下一次还要重新讲。

写进 Skill 后，它就变成可复用资产。

这也是 Skill 和普通提示词最大的区别。

普通提示词像一次性便签。

Skill 像一本可以反复翻的工作手册。

## Skill 和提示词有什么区别？

很多人会问：

那我直接写一个长提示词不就行了吗？

可以。

但长提示词适合临时任务。

Skill 适合长期重复任务。

可以这样理解：

| 类型 | 像什么 | 适合场景 |
|------|--------|----------|
| 提示词 | 临时交代一句话 | 偶尔问一次、临时生成内容 |
| Skill | 固定工作手册 | 经常重复、规则很多、容易漏步骤 |
| 项目说明 | 公司制度和项目规矩 | 让 AI 理解一个长期项目 |

如果你只是让 AI 帮你写一段朋友圈文案，提示词就够了。

如果你每周都要写同一种风格的文章，就适合做 Skill。

如果你让 AI 长期参与一个项目，就需要项目说明加 Skill。

## 普通人现在要不要学 Skill？

如果你只是偶尔用 AI 聊天，不用急。

先学会写清楚提示词就够了。

但如果你已经开始让 AI 帮你做固定工作，Skill 很值得学。

比如你有这些需求：

```text
每周写一篇公众号
每天整理客户反馈
经常让 AI 改同一个项目
反复生成同一种格式的报告
每次发布内容都有固定步骤
```

那 Skill 就能帮你省很多重复沟通。

你可以从一个最小 Skill 开始。

不用写得很复杂。

先写三件事就够：

```text
这个 Skill 什么时候用
做事步骤是什么
有哪些不能犯的错
```

比如：

```text
当我说“写技趣星球文章”时，使用这个 Skill。

步骤：
1. 先用生活场景开头
2. 给一句话结论
3. 用表格解释概念
4. 至少给 2 个可复制提示词
5. 结尾给下一步行动

注意：
- 不要写成论文
- 不要堆专业词
- 不要制造焦虑
```

这已经是一个有用的 Skill 雏形。

```text
我想为自己设计一个 AI Skill。

我的固定任务是：
[写下你经常重复做的一件事，比如写周报、整理会议纪要、写公众号文章]

请帮我整理成一个 Skill 说明，包括：
1. 什么时候使用这个 Skill
2. 具体做事步骤
3. 输出格式
4. 需要避免的错误
5. 给我一个可以直接保存成 Markdown 的版本

要求：
用普通人能看懂的话写，不要写得像技术文档。
```

最后顺手带一句 MCP。

Skill 和 MCP 有关系，但不是同一个东西。

Skill 像「办事说明书」，告诉 AI 该怎么做。

MCP 像「工具插座」，让 AI 能接上外部工具。

这篇先把 Skill 搞懂就够了。

下一篇我们再单独讲 MCP。

到时候你会更容易理解：

为什么现在很多 AI 工具都在接 MCP？

为什么它不像普通插件那么简单？

以及普通人到底要不要折腾它。
